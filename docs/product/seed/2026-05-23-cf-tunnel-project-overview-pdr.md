# Project Overview & Design Document: CF Tunnel Desktop
## Cloudflare Local Tunnel Manager for Windows

---

## 1. Problem Statement & Requirements
Developers need a simple, native, and lightweight Windows application to expose their local development services (like `http://localhost:3000`, `http://localhost:8080`) to the public internet using custom domains via **Cloudflare Tunnel (cloudflared)**.

---

## 2. Scope Definition

### In Scope (MVP):
- **Manual Endpoint Management:** Users manually input local target URLs (e.g., `http://localhost:3000`) and map them to subdomains.
- **Config Persistence:** Configurations are stored locally in a structured JSON file, excluding raw secrets.
- **Run in Background (System Tray):** Closing the app window minimizes it to the system tray while keeping the tunnel active.
- **Autostart on Boot:** The app registers with Windows startup, launches hidden, and restores active tunnels automatically.
- **Secure Token Storage:** Sensitive API tokens and tunnel tokens are stored in the **Windows Credential Manager** via the system keyring.
- **Single Instance Lock:** Enforces a single running instance of the application to prevent process and port conflicts.

### Out of Scope (MVP):
- **Docker Label Scanning:** No automatic scanning of Docker containers or containers' configuration metadata.
- **Complex Databases:** No external database engines like Redis, PostgreSQL, or SQLite.
- **Multi-host / Agent Synchronization:** Strictly designed for a single local machine.
- **Cloudflare Access SSO Policies:** Advanced Cloudflare Access rules and login walls are excluded.
- **Auto-Discovery:** No automated scanning for local network devices.
- **OAuth Authentication:** Access is configured purely using user-provided API tokens.

---

## 3. Architecture & Technology Stack
The application is designed using a modern, lightweight, and secure desktop framework:

- **Frontend:** React + TypeScript + Vite + Vanilla CSS (polished dark-mode/glassmorphism UI).
- **Backend (Tauri v2 + Rust):**
  - Manages the local JSON configuration file (non-sensitive metadata).
  - Directly interacts with the Cloudflare API for Zone management, DNS CNAME updates, and remote Tunnel configurations.
  - Controls the `cloudflared` binary packaged as a Tauri **Sidecar** (`cloudflared-x86_64-pc-windows-msvc.exe`).
  - Manages Windows System Tray, custom menus, and intercepts window close events.
  - Interfaces with Windows Credential Manager via the `keyring` Rust crate to secure secrets.
- **Tauri Plugins:**
  - `@tauri-apps/plugin-autostart`: Handles registry integration for autostarting on Windows.
  - `@tauri-apps/plugin-shell`: Manages spawning, monitoring, and killing the `cloudflared` sidecar process.
  - `@tauri-apps/plugin-store`: Handles local configuration file operations.
  - `@tauri-apps/plugin-single-instance`: Enforces a single app instance.

## 4. Core Data Structures (Entities)

### `CloudflareProfile`
Stores user credentials for Cloudflare API interaction. The actual token is stored in the keyring.
```typescript
interface CloudflareProfile {
  accountId: string;
  zoneId: string;
  domain: string;
  apiTokenRef: string;    // Key identifier used to retrieve API Token from Windows Credential Manager
  email?: string;
}
```

### `TunnelConfig`
Holds the details of the active Cloudflare Tunnel. The actual tunnel token is stored in the keyring.
```typescript
interface TunnelConfig {
  tunnelId: string;
  tunnelName: string;
  tunnelTokenRef: string; // Key identifier used to retrieve Tunnel Token from Windows Credential Manager
}
```

### `Route`
Defines an exposed endpoint mapping. Incorporates DNS record ownership to avoid deleting user-created external records.
```typescript
interface Route {
  id: string;
  hostname: string;       // e.g., "api.mycustomdomain.com"
  targetUrl: string;      // e.g., "http://localhost:8080"
  enabled: boolean;       // Toggle state
  dnsRecordId?: string;   // Cloudflare DNS Record ID, used to delete only app-owned records
}
```

## 5. Security & Secret Management

### 5.1 Credential Storage & Keyring Integration
- **Zero Plain-Text Secrets:** API Tokens and Tunnel Tokens are never saved in the plain JSON config file.
- **Unidirectional Secret Flow (Post-Onboarding):**
  - During onboarding, the user inputs the token in the frontend, which is immediately sent to the Rust backend for verification and storage.
  - **After initial submission, raw tokens are never returned to the frontend.**
  - Rust exposes Tauri commands: `save_cloudflare_token(token)`, `validate_cloudflare_profile()`, `create_route(routeInput)`, and `get_connection_status()`.
  - When the frontend requests profiles, the backend returns redacted data structures where secrets are hidden.
- **Token Rotation & Deletion:**
  - **Rotation:** If the user replaces a token, the backend validates it and overwrites the existing entry in the Windows Credential Manager.
  - **Deletion:** Wiping a profile completely deletes the corresponding credentials from the Windows Credential Manager.

### 5.2 Command-Line Process Security
- **Process Inspection Risk:** Running `cloudflared tunnel run --token <token>` exposes the token in the Windows command line parameters.
- **Mitigation Policies:**
  - Future iterations will evaluate utilizing credentials files with strict Access Control Lists (ACLs) restricted to the current user.
  - For the MVP:
    - Raw tokens are redacted from all application logs.
    - Full CLI command-line strings containing secrets are never exposed to the frontend or logged.
    - Sidecar processes are spawned strictly from Rust.

## 6. Workflows & Lifecycle

### 6.1 Process Lifecycle & Cleanup Policy
- **PID Lockfile:** The app writes the PID of its spawned sidecar to a dedicated file: `AppData/Local/cftunneldesktop/cloudflared.pid`.
- **Termination Policy:**
  - **Window Close [x]:** The window hides to the system tray, keeping the tunnel process alive.
  - **Tray "Quit" Action:** The Rust backend kills only the `cloudflared` process matching the saved PID and exits the app.
  - **Startup Cleanup:** On startup, the app checks the PID file for any orphan processes from a previous crash. If found, it kills only that process before starting a fresh instance. It never runs blind process kills (e.g., `taskkill /f /im cloudflared.exe`) to avoid affecting unrelated tunnels.

### 6.2 Reconciliation & Drift Policy
- **Source of Truth:** The local configuration JSON is the **Desired State** (Source of Truth). The Cloudflare Dashboard represents the **Remote Actual State**.
- **Drift Handling:** If the user modifies DNS or Ingress rules directly on Cloudflare, the app detects the drift during periodic sync or manual trigger.
- **Action Policy:** The app alerts the user of the configuration drift via a warning banner and prompts them before applying reconciliation (overwriting remote state to match local settings). It will not auto-overwrite destructively without user consent.

### 6.3 Offline Behavior (Autostart)
- **No Gatekeeper Pings:** The app does not ping `1.1.1.1` to check for internet connectivity, avoiding corporate firewall/ICMP blocks.
- **Asynchronous Sync Loop:**
  - On autostart, the app launches hidden and immediately spawns the `cloudflared` process (which natively handles connection retries with exponential backoff).
  - The reconciliation sync with Cloudflare API runs in the background using a short timeout.
  - If the sync fails due to network issues, the app enters a `Waiting for network` state and schedules a retry with exponential backoff + jitter, without blocking the UI or sending spam notifications.

## 7. UX Minimum Screens Checklist

1. **Onboarding Screen:**
   - Enter Cloudflare API Token, Account ID, and Zone ID.
   - "Test Connection" button to validate credentials and save API Token to Windows Credential Manager.
2. **Tunnel Setup Screen:**
   - Option to create a new Tunnel (auto-names it `cf-tunnel-desktop`) or select an existing remotely-managed Tunnel.
3. **Route Table (Dashboard):**
   - Table displaying configured routes: `Subdomain`, `Target URL`, `Status Toggle (On/Off)`.
   - Banner warning if configuration drift is detected.
   - "Add Route" modal form.
   - Delete/Edit actions.
4. **Log Console Screen:**
   - Real-time output display of the `cloudflared` stdout/stderr stream (redacted of secrets).
   - "Clear Logs" and "Copy to Clipboard" buttons.
5. **Settings Screen:**
   - "Run on Windows Startup" checkbox.
   - "Close to Tray" checkbox.
   - "Clear Data" (wipes local config and credentials).
6. **System Tray Menu:**
   - Right-click menu: `Show Window`, `Start All Tunnels`, `Stop All Tunnels`, `Open Logs`, `Launch on Startup: On/Off`, `Quit`.

## 8. Target Validation Rules

To prevent unsafe or invalid mappings, the app enforces target URL validation:
- **Allowed Schemes:** `http://` and `https://`.
- **Allowed Targets:** `localhost`, `127.0.0.1`, `[::1]`, or loopback ports.
- **Warnings:** Display a warning if the target is a private LAN IP (e.g., `192.168.x.x`, `10.x.x.x`).
- **Blocked:** Block invalid schemes (e.g., `file://`, `ftp://`).

---

## 9. Non-Functional Requirements & Pinned Sidecar

### Pinned Sidecar Policy
- **No Floating Updates:** To ensure reproducible builds and prevent supply-chain attacks, the `cloudflared` version is strictly pinned.
- **Version Configuration:**
  ```json
  {
    "cloudflaredVersion": "2026.5.1",
    "windowsX64Sha256": "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855"
  }
  ```
- **Build Hook Script:** A PowerShell script `download-sidecar.ps1` downloads the specific version, verifies its SHA256 checksum, renames it to `cloudflared-x86_64-pc-windows-msvc.exe`, and places it in `src-tauri/binaries/`. The build fails if the binary is missing or checksum verification fails.

### Requirements:
- **Startup Performance:** App starts hidden or visible in under 2.0 seconds.
- **Process Memory Limits:**
  - **Tauri Host (Rust) Process:** Resident Set Size (RSS) under 30MB while minimized.
  - **cloudflared Process:** RSS under 30MB.
  - *(WebView2 chromium processes are excluded from the 60MB ceiling, but the total bundle footprint must aim to remain under 150MB).*
- **Log Retention:** In-memory logs capped at 1000 lines.
- **Target OS:** Windows 10/11 x64.

## 10. Measurable Acceptance Criteria

| Requirement | Test Scenario | Acceptance Criteria (State Observed) |
|-------------|---------------|--------------------------------------|
| **Expose Route** | Add route `api.domain.com` -> `http://localhost:8080` | Cloudflare API returns success for Ingress update and CNAME creation in **< 10 seconds** (under stable network). |
| **Secret Storage** | Open local config JSON file | Ensure `apiToken` or `tunnelToken` are NOT present in plain text; verify credentials exist in Windows Credential Manager / keyring backend. |
| **Autostart & Restore** | Restart Windows | App launches minimized to tray, automatically reads local configs, and starts the `cloudflared` process successfully without user action. |
| **Disable Route** | Toggle off a route | The route is disabled (removed from Cloudflare tunnel configuration ingress rules) in **< 5 seconds**, while keeping the DNS CNAME record in place. |
| **Delete Route** | Click delete on a route | The route is removed from tunnel configurations AND the app-owned DNS CNAME record (matching `dnsRecordId`) is deleted on Cloudflare in **< 5 seconds**. |
| **Process Isolation** | Check Task Manager | Ensure other running `cloudflared` processes (unrelated to this app) remain completely unaffected when starting/stopping the app. |
